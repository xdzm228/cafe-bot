# Telegram-бот для кафе

Бот на Python (aiogram 3) із трьома функціями:

- 📅 **Бронювання столика** — користувач проходить короткий діалог (ім'я, телефон, кількість гостей, дата, час, коментар), бронювання зберігається в БД, а сповіщення надходить адміну.
- 📢 **Розсилки за потреби** — команда `/broadcast` дозволяє адміну будь-якої миті розіслати новину/повідомлення (текст, фото, відео) всім користувачам бота.
- 📊 **Опитування** — команда `/poll` створює опитування (запитання + варіанти відповіді) і розсилає його всім користувачам.

## Встановлення

1. Встановіть Python 3.10+.
2. Створіть віртуальне середовище та встановіть залежності:

   ```bash
   python -m venv venv
   source venv/bin/activate   # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. Отримайте токен бота у [@BotFather](https://t.me/BotFather).
4. Дізнайтеся свій Telegram user_id у [@userinfobot](https://t.me/userinfobot).
5. Скопіюйте `.env.example` у `.env` і заповніть:

   ```
   BOT_TOKEN=ваш_токен
   ADMIN_IDS=ваш_id
   ```

6. Запустіть бота:

   ```bash
   python bot.py
   ```

## Команди користувача

- `/start` — привітання та головне меню
- Кнопка «📅 Забронювати столик» — почати бронювання
- Кнопка «ℹ️ Про кафе» — контакти та час роботи

## Команди адміністратора (доступні лише ID з ADMIN_IDS)

- `/admin` — коротка довідка та кількість користувачів у базі
- `/broadcast` — почати розсилку (наступне повідомлення піде всім)
- `/poll` — створити та розіслати опитування
- `/reservations` — останні 15 бронювань
- `/cancel` — скасувати поточну дію (розсилку/опитування/бронювання)

## Як це влаштовано

- **aiogram 3** — асинхронний фреймворк для Telegram-ботів, FSM (машина станів) використовується для покрокових діалогів бронювання, розсилки та опитування.
- **SQLite** (через `aiosqlite`) — зберігає користувачів (для розсилок) і бронювання столиків. Файл `cafe_bot.db` створюється автоматично під час першого запуску.
- Розсилка йде з невеликою затримкою між повідомленнями (`asyncio.sleep(0.05)`), щоб не впертися в ліміти Telegram (~30 повідомлень/сек).

## Що можна доопрацювати

- Інлайн-кнопки підтвердження/скасування бронювання для адміна (прийняти/відхилити).
- Перевірка зайнятості столиків на конкретний час (наразі бронювання просто складаються у список).
- Планувальник (`APScheduler`) для розсилок за розкладом, якщо захочете не лише «за потреби», а й автоматично.
- Вебхуки замість long polling для продакшена (наприклад, на VPS з nginx).
