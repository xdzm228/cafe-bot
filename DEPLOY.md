# Деплой бота для постійної роботи (24/7)

Зараз бот працює, поки у вас відкритий PyCharm і натиснута кнопка ▶.
Якщо закрити ноутбук — бот вимкнеться. Щоб він працював постійно,
його треба перенести на **сервер**, який ніколи не вимикається.

Нижче — три варіанти, від найпростішого до найгнучкішого. Оберіть один.

---

## Варіант A. Хостинг-платформа без сервера (найпростіше)

Підходить, якщо не хочете возитися з Linux і командним рядком.
Приклад — **Railway** (є безкоштовний ліміт, потім platна підписка від ~5$/міс).

1. Зареєструйтесь на [railway.app](https://railway.app) через GitHub.
2. Завантажте код проєкту на GitHub:
   - Створіть новий репозиторій (наприклад, `cafe-bot`), **не публічний**, якщо не хочете світити код.
   - У папці проєкту виконайте:
     ```
     git init
     git add .
     git commit -m "init"
     git branch -M main
     git remote add origin https://github.com/ВАШ_НІК/cafe-bot.git
     git push -u origin main
     ```
   - Файл `.env` у git **не потрапить** — він у `.gitignore`, це правильно, токен там світити не можна.
3. У Railway: **New Project → Deploy from GitHub repo** → оберіть свій репозиторій.
4. Railway сам побачить `Dockerfile` і збере контейнер.
5. У вкладці **Variables** додайте змінні оточення (ті самі, що у вашому `.env`):
   ```
   BOT_TOKEN=ваш_токен
   ADMIN_IDS=ваш_id
   CAFE_NAME=Затишний куточок
   CAFE_ADDRESS=вул. Прикладна, 1
   CAFE_HOURS=09:00–23:00
   CAFE_PHONE=+380 00 000 00 00
   ```
6. Railway задеплоїть і запустить бота автоматично. При падінні — перезапустить сам.
7. Логи дивіться у вкладці **Deployments → View Logs**.

Аналогічно працює на **Render.com** (є безкоштовний план, але контейнер засинає без активності — для бота з polling це не проблема, засинання актуальне для веб-серверів) та **Amvera** (український/СНД-орієнтований хостинг, зручно для оплати).

## Варіант B. VPS + Docker (рекомендовано для контролю)

Підходить, якщо хочете повний контроль і плануєте додавати інші сервіси.

### 1. Орендуйте VPS
Наприклад, **Hetzner**, **DigitalOcean**, **Timeweb Cloud** — від ~$4-5/міс.
Оберіть Ubuntu 22.04 або 24.04.

### 2. Підключіться по SSH
```
ssh root@ВАША_IP_АДРЕСА
```

### 3. Встановіть Docker
```
curl -fsSL https://get.docker.com | sh
apt install docker-compose-plugin -y
```

### 4. Перенесіть проєкт на сервер
Найпростіше — через `git` (якщо вже завантажили на GitHub, див. Варіант A, крок 2):
```
git clone https://github.com/ВАШ_НІК/cafe-bot.git
cd cafe-bot
```
Або через `scp` зі свого комп'ютера (виконати у себе локально, не на сервері):
```
scp -r D:\cafe_bot root@ВАША_IP_АДРЕСА:/root/cafe_bot
```

### 5. Створіть `.env` на сервері
```
cd cafe_bot
nano .env
```
Вставте вміст (як у `.env.example`, але з реальним токеном), збережіть — `Ctrl+O`, `Enter`, вихід — `Ctrl+X`.

### 6. Запустіть
```
docker compose up -d --build
```
Прапорець `-d` — запуск у фоні, `--build` — зібрати образ.

### 7. Перевірте, що працює
```
docker compose logs -f
```
Побачите рядок `Бот запущено, починаю polling...` — все ок. `Ctrl+C` виходить з перегляду логів, бот при цьому продовжує працювати.

### 8. Корисні команди
```
docker compose down          # зупинити бота
docker compose up -d         # запустити знову
docker compose restart       # перезапустити
docker compose logs -f       # дивитись логи наживо
```

Завдяки `restart: unless-stopped` у `docker-compose.yml` бот сам підніметься після
перезавантаження сервера чи падіння процесу.

## Варіант C. VPS без Docker, через systemd

Якщо не хочете розбиратись з Docker — можна запустити напряму через Python
і доручити автозапуск/автоперезапуск systemd (стандартний менеджер служб у Linux).

### 1-2. Оренда VPS та SSH — як у Варіанті B.

### 3. Встановіть Python і залежності
```
apt update
apt install python3 python3-venv python3-pip -y
```

### 4. Перенесіть проєкт (git clone або scp, як у Варіанті B, крок 4)

### 5. Створіть віртуальне середовище і встановіть залежності
```
cd cafe_bot
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 6. Створіть `.env` (як у Варіанті B, крок 5)

### 7. Налаштуйте systemd-службу
У проєкті вже є готовий файл `cafe-bot.service`. Відредагуйте в ньому шляхи
та користувача під ваш сервер (за замовчуванням очікується користувач `botuser`
і шлях `/home/botuser/cafe_bot` — замініть на свої, наприклад `root` і `/root/cafe_bot`).

Скопіюйте його в системну папку:
```
cp cafe-bot.service /etc/systemd/system/cafe-bot.service
systemctl daemon-reload
systemctl enable cafe-bot
systemctl start cafe-bot
```

### 8. Перевірте статус і логи
```
systemctl status cafe-bot
journalctl -u cafe-bot -f
```

### 9. Керування
```
systemctl stop cafe-bot       # зупинити
systemctl restart cafe-bot    # перезапустити
systemctl disable cafe-bot    # прибрати з автозапуску
```

`Restart=always` у файлі служби гарантує, що бот сам підніметься після падіння
чи перезавантаження сервера.

## Що обрати?

| Варіант | Складність | Контроль | Вартість |
|---|---|---|---|
| A. Railway/Render | Найпростіше, без термінала Linux | Обмежений | Безкоштовно з лімітами, далі від ~$5/міс |
| B. VPS + Docker | Середня | Повний | від ~$4-5/міс |
| C. VPS + systemd | Середня, без Docker | Повний | від ~$4-5/міс |

Для старту й перевірки ідеї — беріть **Варіант A**. Якщо плануєте розвивати
бота і додавати інші сервіси (наприклад, адмінку) — краще одразу **Варіант B**.

## Важливо для безпеки

- Ніколи не публікуйте `.env` і не комітьте його в git — там ваш токен.
  Якщо токен випадково засвітився — одразу перевипустіть його у @BotFather
  командою `/revoke`.
- На VPS бажано створити окремого користувача (не `root`) для запуску бота
  і налаштувати firewall (`ufw allow OpenSSH`, `ufw enable`).
- Регулярно робіть бекап файлу `cafe_bot.db` (у Docker він лежить у `./data/cafe_bot.db`
  на хост-машині) — там зберігаються всі бронювання.
